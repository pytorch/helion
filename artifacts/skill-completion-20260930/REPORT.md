## Changes and scope

The CuTe backend now represents recurrent contraction graphs with shared storage, dependency and execution plans. Native prefill schedules, prepared warp tiles, scan producers, tensor-memory transfers and external state copies use those plans. Alternative schedules and storage choices are exposed through the autotuner's search space and seeds.

The general positional fallback preserves distinct tensor coordinates when equal-sized axes share a canonical layout axis. It also handles contractions whose reduction spans synthetic lanes. Logical extents bound partial reductions, scans and store indexers while preserving explicit full-width operand semantics. Shared contraction handling covers dot, mm, bmm and baddbmm; snapshots preserve values across aliased writes, serial carries and host-uniform branches. Native roots retain priority, and the fallback checks its full shared-memory requirement before emission. Scalar-only tensor views can use element alignment after the launcher proves their access pattern; vector accesses and escaped pointers retain their existing requirements.

Autotuning now isolates candidate inputs during compilation and timing so mutating kernels cannot contaminate later candidates. Optional profiler timing checks clock domains and search evidence. Benchmark changes add fused KDA implementations and reproducible backend comparisons.

The main risks are broad compiler coverage and runtime specialization: the graph planner and positional fallback affect kernels beyond the measured variants, and alignment-sensitive launcher keys invalidate cached compilations. Candidate input isolation and profiler timing affect autotuning across backends. Compiler metadata and runtime code changed; the Helion frontend language did not.
